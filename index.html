Real-Time Game Appearance Alerts

Graceffo Alert automatically monitors official MLB game data and delivers SMS notifications when Gordon Graceffo enters a St. Louis Cardinals game.

This is a personal notification service for a fixed group of approved recipients. It is engineered for resilience, built with production-style operational safeguards, and provides informational updates only.

How It Works

1. Official MLB Game Feed

The system reads live game-state updates from official MLB data endpoints and validates update sequence integrity before processing.

2. Graceffo Appearance Detection

Detection logic continuously evaluates roster and pitching events to confirm a real in-game entry condition before triggering notifications.

3. Notification Engine

A campaign-driven engine creates a controlled send operation with recipient validation, retry policy, and provider routing safeguards.

4. SMS Delivered to Approved Recipients

Messages are delivered only to explicitly enrolled recipients, with outcome tracking recorded in a delivery ledger for verification and audits.

Built Like a Production Service

Provider Abstraction

A dedicated provider layer decouples business logic from vendor APIs, enabling portability and controlled failover without rewriting campaign logic.

Retry Engine

Structured retry orchestration addresses transient failures while enforcing bounded retry windows to avoid duplicate or runaway delivery behavior.

Redis Persistence

Redis stores campaign and processing state so execution can recover cleanly after restart, preserving operational continuity across process interruptions.

Campaign State Management

A campaign state machine enforces explicit transitions from detection through completion, reducing ambiguity and preventing inconsistent send paths.

Delivery Ledger

An append-only ledger captures send attempts and outcomes to support traceability, incident review, and confidence in final delivery status.

Circuit Breaker

Circuit breaker controls prevent repeated calls into degraded provider dependencies, protecting the service and supporting graceful degradation.

Runtime Diagnostics

Runtime diagnostics expose campaign-level visibility so operators can rapidly inspect active state, delivery attempts, and error conditions.

Operational Telemetry

Telemetry captures latency, failure classes, and recovery outcomes to support reliability tuning and faster troubleshooting over time.

Designed for Reliable Delivery

Graceffo Alert is designed around predictable delivery behavior under real-world conditions. Retry policies and state persistence work together so transient failures do not immediately result in missed notifications.

The service prioritizes failure recovery and observability. Campaign state can be resumed after process interruptions, and operational telemetry makes delivery paths inspectable when incidents occur.

Provider independence reduces single-vendor risk. If a messaging dependency experiences temporary instability, circuit controls and retry orchestration help the system continue operating gracefully until the provider recovers.

System Flow

Campaign Timeline

  1. Monitoring: Live game data is continuously evaluated for player activity changes.
  2. Appearance Detected: Entry criteria validates that Gordon Graceffo is actively in game.
  3. Campaign Created: A campaign instance is initialized with state, recipients, and delivery policy.
  4. SMS Delivery: Initial send is attempted through the active messaging provider.
  5. Retry (if necessary): Transient delivery failures trigger bounded retries with backoff.
  6. Campaign Complete: Final status is persisted in the ledger for audit and operational review.
