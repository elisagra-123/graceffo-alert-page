System Architecture

Graceffo Alert is intentionally engineered as a compact but production-style event notification pipeline.

Core Components

Feed Monitor

The monitor ingests official MLB game updates and normalizes event data into deterministic signals consumed by detection logic.

Appearance Detector

Detection guards prevent false triggers by requiring confirmed in-game presence before any campaign can be created.

Campaign State Machine

State transitions formalize lifecycle boundaries, ensuring each campaign moves through valid steps with explicit completion criteria.

Provider Interface

A provider abstraction isolates external messaging APIs so reliability policy remains consistent across implementation changes.

Retry Orchestrator

Retry orchestration handles transient delivery failures through bounded backoff, reducing dropped messages without creating unbounded send behavior.

Delivery Ledger

The ledger records send attempts, responses, and terminal outcomes to support operational accountability and incident diagnostics.

Redis Persistence

Redis stores campaign and queue context so processing can resume cleanly after process restart or host interruption.

Telemetry + Diagnostics

Structured telemetry and runtime diagnostics provide visibility into latency, failure rates, and campaign health.

Design Objectives

  • Maintain accurate trigger semantics from official game data.
  • Deliver informational SMS updates to consented recipients with controlled retry behavior.
  • Preserve state across restarts for predictable campaign continuity.
  • Minimize vendor lock-in through provider-independent interfaces.
  • Support rapid troubleshooting through auditable delivery history and telemetry.
